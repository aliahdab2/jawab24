# Language Support — Jawab24

> **Updated 2026-04-15** — Reflects migration to `next-intl` v4 with namespaced translation files.

## Overview
Jawab24 supports **full bilingual operation** in Arabic and English, with special support for Arabic dialects (Syrian, Gulf, Egyptian, etc.).

---

## Supported Languages

### Primary Languages
- **Arabic (العربية)** - Full support
  - Modern Standard Arabic (MSA)
  - Syrian Dialect (اللهجة الشامية) - Primary focus
  - Other dialects supported via AI language detection
- **English** - Full support

---

## Language Support Areas

### 1. Dashboard UI (next-intl v4)

**Technology:**
- `next-intl` v4 with **44 namespaced translation files** per language
- File structure: `frontend/src/i18n/en/<namespace>.json` + `ar/<namespace>.json`
- Next.js locale routing for URL-based language switching (`/en/...`, `/ar/...`)
- RTL (Right-to-Left) support via CSS logical properties
- Automated validation via `npm run translation:validate`
- ICU Message Format for pluralization

**File Structure:**
```
frontend/src/i18n/
  en/                   # 44 namespace files
    common.json         # Shared strings
    dashboard.json      # Dashboard page
    settings.json       # Settings page
    comments.json       # Comments page
    messages.json       # Messages page
    nav.json            # Navigation/sidebar
    ...
  ar/                   # Mirrors en/ structure
  getMessages.ts        # Static imports + NS lookup table
  namespaces.ts         # PAGE_NAMESPACES mapping
  hooks.ts              # useLanguage() for switching + dateLocale
  index.ts              # Re-exports
```

**Usage in Components:**
```tsx
import { useTranslations, useLocale } from 'next-intl';
import { useLanguage } from '@/i18n';
import { isRTLLocale } from '@/utils/locale';

export default function Dashboard() {
  const t = useTranslations('dashboard');     // namespace-scoped
  const tc = useTranslations('common');       // shared strings
  const locale = useLocale();
  const { setLanguage } = useLanguage();
  const isRTL = isRTLLocale(locale);

  return (
    <div>
      <h1>{t('title')}</h1>
      <button onClick={() => setLanguage('ar')}>العربية</button>
      <button onClick={() => setLanguage('en')}>English</button>
      <button>{tc('save')}</button>
    </div>
  );
}
```

**Page Loading — Only required namespaces are loaded per page:**
```tsx
// In page file
export const getStaticProps = makeGetStaticProps(['settings', 'time']);
```

Global namespaces auto-loaded: `common`, `nav`, `notifications`, `errors`, `errorBoundary`, `meta`.

**Interpolation** uses single braces `{variable}`:
```json
"greeting": "Hello, {name}!"
"stats": "{count} items remaining"
```
```tsx
t('greeting', { name: userName })
```

**Pluralization** uses ICU Message Format:
```json
// English
"itemCount": "{count, plural, one {# item} other {# items}}"

// Arabic (all 6 forms)
"itemCount": "{count, plural, zero {لا عناصر} one {عنصر واحد} two {عنصران} few {# عناصر} many {# عنصر} other {# عنصر}}"
```

**Validation** — run before committing translation changes:
```bash
npm run translation:validate
```

See `frontend/docs/TRANSLATION_GUIDE.md` for full rules (key naming, RTL, brand terms, namespace registration).

### 2. Backend i18n

**Customer-facing strings** (nudges, fallbacks, placeholders) live in `backend/src/utils/i18n.ts`:

```tsx
import { t } from '../utils/i18n';

const message = t('greeting', lang);  // returns AR or EN string
```

**Language detection** uses `detectLanguageOrNull()` in `ai-worker/src/services/openai.ts`:
- Checks for Arabic Unicode characters
- Returns `null` for script-less input (emoji, punctuation) so KB language is used as fallback
- Strips @mentions before detection to avoid Latin name bias

**Auto-translation service** (`backend/src/services/translation.ts`):
- Away/greeting messages auto-translated on save
- Both `*_ar` and `*_en` variants stored in DB
- System picks variant by customer's detected language

---

### 3. AI Replies

**Automatic language handling:**
- AI detects comment/message language
- Replies in the same language
- Falls back to KB language, then user preference
- Prompt version v30 handles dialect-aware replies

**The AI prompt system** is in `packages/shared/src/index.ts` — it instructs the model to mirror the customer's dialect and language naturally.

## Settings

Workspace-level language settings:
- **Dashboard Language**: Controlled by URL locale (`/en/...` or `/ar/...`)
- **Default Reply Language**: Fallback when detection is uncertain
- **Auto-detect language**: Always enabled (AI detects per-message)

## Common Mistakes

| Mistake | Fix |
|---------|-----|
| `useTranslation` from `@/i18n` | `useTranslations` from `next-intl` with namespace |
| `t('namespace.key')` | Drop prefix: `t('key')` — namespace set at hook level |
| `locale === 'ar'` | `isRTLLocale(locale)` from `@/utils/locale` |
| `language === 'ar' ? 'rtl' : 'ltr'` | `getLocaleDirection(locale)` |
| Flat `en.json` / `ar.json` | Namespaced: `en/<namespace>.json` + `ar/<namespace>.json` |
| Missing `getMessages.ts` registration | Raw keys in production (tests still pass) |

---

## Best Practices

1. **Always add keys to both `en/` and `ar/` namespace files**
2. **Register new namespaces in 4 places** (see `AI_INSTRUCTIONS.md` section 5)
3. **Use ICU Message Format** for pluralization (Arabic needs all 6 forms)
4. **Use CSS logical properties** for RTL — never physical left/right
5. **Use `isRTLLocale(locale)`** — never `locale === 'ar'`
6. **Run `npm run translation:validate`** before committing
7. **Use `dir="auto"` on user-editable inputs/textareas** — the EMPTY-field fallback to LTR is fixed globally in `globals.css` (`:placeholder-shown { direction: inherit }`), so no per-component conditional is needed. See AI_INSTRUCTIONS.md §10.4.
